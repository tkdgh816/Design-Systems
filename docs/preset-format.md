# 프리셋 규격

프리셋의 추가·수정·복제 단위는 `presets/<id>/` 폴더 하나입니다. ID에는 영문 소문자, 숫자, 단어 사이의 하이픈을 사용합니다. 표시 이름은 자유롭게 정합니다. 아래 경로는 프리셋을 제작할 때 적용할 구조입니다.

| 프리셋 내부 경로 | 담는 내용 | 작성 시점 |
| --- | --- | --- |
| `preset.json` | 탐색에 사용할 메타데이터. `id`, `name`, `description`은 문자열, `tags`는 문자열 배열입니다. | 프리셋을 등록할 때 |
| `design.md` | 대상과 사용 상황, 디자인 철학, 정보 위계와 배치, 색상·서체 선택의 이유, 주요 컴포넌트의 역할과 상태 | 설계를 기록할 때 |
| `tokens.json` | 색상, 타이포그래피, 간격, 모서리 반경, 그림자 등 여러 화면에서 재사용할 값 | 토큰을 정의할 때 |
| `assets/` | 프리셋에서 사용하는 아이콘, 이미지, 배포 가능한 폰트 등. 외부 에셋은 출처와 사용 조건을 함께 기록합니다. | 에셋이 있을 때 |
| `preview/` | 대표 화면의 미리보기. `design.md`에서 시작 파일이나 이미지에 상대 경로로 연결합니다. | 시각 검토용 화면을 만들 때 |
| `implementations/<platform>/` | 웹, 모바일, 데스크톱 등 대상 플랫폼의 토큰 변환 코드와 컴포넌트 구현 예시 | 재사용할 구현이 생길 때 |

## 토큰 작성 기준

- 이름은 쓰임새를 드러냅니다. 예를 들어 `color.text.primary`는 기본 본문색을 가리킵니다. 특정 프레임워크의 클래스명이나 컨트롤 이름은 플랫폼 구현에서 매핑합니다.
- 각 토큰에 타입과 값을 기록합니다. 색상에는 색 표현 형식을 명시하고, 간격·반경·글자 크기에는 수치와 기준 단위를 함께 기록합니다. 굵기처럼 단위가 없는 값은 숫자로 기록합니다.
- 타이포그래피는 글꼴·크기·굵기·행간을, 그림자는 오프셋·흐림·색상 등 재현에 필요한 값을 구분합니다. 플랫폼별 단위 환산과 테마 연결은 해당 구현에서 처리합니다.
- 공통 키 표기, 값의 직렬화 형식, 참조 문법은 첫 프리셋 제작 전에 [로드맵 2단계](../ROADMAP.md)에서 확정합니다.

## 독립성 확인

프리셋 내부 파일은 해당 폴더를 기준으로 상대 경로로 연결합니다. 폴더를 다른 위치에 복사한 뒤에도 원칙과 토큰을 읽고, 포함된 에셋과 미리보기를 열 수 있어야 합니다. 다른 프리셋의 파일이나 개인 PC의 절대 경로에 의존하는 참조는 작성하지 않습니다.
