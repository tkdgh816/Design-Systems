# 프리셋 규격

프리셋의 추가·수정·복제 단위는 `presets/<id>/` 폴더 하나입니다. 등록에 필요한 파일은 `preset.json`, `design.md`, `tokens.json`입니다. 나머지 파일은 해당 프리셋이 제공하는 기능에 따라 추가합니다.

| 프리셋 내부 경로 | 담는 내용 | 작성 시점 |
| --- | --- | --- |
| `preset.json` | 탐색에 사용할 메타데이터. `id`, `name`, `description`은 문자열, `tags`는 문자열 배열입니다. | 프리셋을 등록할 때 |
| `design.md` | 대상과 사용 상황, 디자인 원칙, 그 원칙이 화면에 드러나는 특징, 기본 접근성 고려사항 | 프리셋을 등록할 때 |
| `tokens.json` | 기본 테마의 역할 키, 타입, 값과 참조. 이 파일만으로 기본 테마를 해석할 수 있어야 합니다. | 프리셋을 등록할 때 |
| `themes/<theme>.json` | 기본 테마에서 값이 달라지는 토큰 | 추가 테마를 지원할 때 |
| `assets/` | 프리셋에서 사용하는 아이콘, 이미지, 배포 가능한 폰트 등. 외부 에셋은 출처와 사용 조건을 함께 기록합니다. | 에셋이 있을 때 |
| `preview/` | 대표 화면의 미리보기. `design.md`에서 시작 파일이나 이미지에 상대 경로로 연결합니다. | 시각 검토용 화면을 만들 때 |
| `implementations/<platform>/` | 웹, 모바일, 데스크톱 등 대상 플랫폼의 토큰 변환 코드와 컴포넌트 구현 예시 | 재사용할 구현이 생길 때 |

## 메타데이터, 카탈로그와 템플릿

- `preset.json`의 네 필드(`id`, `name`, `description`, `tags`)는 필수입니다. ID는 영문 소문자, 숫자, 단어 사이의 하이픈으로 작성하고 폴더명과 일치시킵니다. 표시 이름은 자유롭게 정합니다. 설명에는 프리셋이 어울리는 사용 상황을 적습니다.
- 카탈로그는 `presets/*/preset.json`을 읽어 구성합니다. 각 프리셋의 메타데이터가 목록의 원본이므로 프리셋을 추가하거나 복제할 때 한 곳에서 정보를 관리할 수 있습니다.
- 제작용 템플릿의 위치는 라이브러리 루트의 `templates/preset/`입니다. 필수 파일 세 개의 골격을 두고, `design.md`에는 “어떤 화면에서 이 원칙이 드러나는가?”처럼 작성자가 답할 질문을 둡니다. 템플릿을 카탈로그의 탐색 경로 밖에 두면 제작 중인 골격과 등록된 프리셋을 구분할 수 있습니다.

## 디자인 원칙과 토큰의 경계

`design.md`에는 사용자에게 어떤 경험을 주려는지, 그 의도를 화면에서 어떻게 확인할지 적습니다. 브랜드 분위기, 레이아웃과 그리드, 아이콘·이미지 스타일, 주요 컴포넌트의 상호작용 상태, 모션, UI 문구 원칙은 해당 프리셋에 필요한 항목만 다룹니다.

예를 들어 키보드 포커스를 어떤 상태에서도 식별할 수 있어야 한다는 원칙은 `design.md`에 적습니다. 이를 표현하는 테두리 색과 두께는 `tokens.json`에 기록합니다. CSS 변수, Tailwind CSS 테마, XAML 리소스, Android 리소스에 연결하는 코드와 단위 변환은 `implementations/<platform>/`에서 관리합니다.

## 토큰의 키, 타입, 단위와 값

저장 형식은 DTCG 2025.10을 따릅니다. 이 프로젝트에서는 사람이 토큰 하나만 읽어도 해석할 수 있도록 각 토큰에 `$type`과 `$value`를 명시합니다. 용도 설명이 필요하면 `$description`을 추가합니다. [DTCG Format Module 2025.10](https://www.designtokens.org/tr/2025.10/format/)

| 항목 | 작성 규칙 |
| --- | --- |
| 키 | JSON 객체를 중첩합니다. 직접 정하는 키에는 영문 소문자, 숫자, 단어 사이의 하이픈을 사용합니다. 점은 문서와 참조에서 경로를 구분합니다. 예를 들어 `color.text.primary`는 `color` 안의 `text` 안에 있는 `primary`입니다. |
| 색상 | 첫 버전에서는 `color` 타입의 값을 sRGB로 기록합니다. `colorSpace`는 `srgb`, `components`는 0 이상 1 이하의 RGB 숫자 세 개입니다. 반투명 색에는 `alpha`를 기록합니다. |
| 길이 | 간격, 글자 크기, 모서리 반경, 테두리 두께의 원본 단위는 `px`입니다. `dimension` 값은 숫자와 단위를 함께 담습니다. 플랫폼별 환산과 사용자 글자 배율은 적용 단계에서 처리합니다. |
| 타이포그래피와 그림자 | `typography`는 글꼴·크기·굵기·자간·행간을, `shadow`는 색상·가로 및 세로 오프셋·흐림·퍼짐을 구분해 기록합니다. 굵기와 행간 배수처럼 단위 없는 값은 숫자로 기록합니다. |
| 참조 | `"{color.text.primary}"`처럼 중괄호 안에 토큰 경로를 씁니다. 참조는 같은 프리셋 안에서 밝기 테마와 지원하는 포인트 색상 선택을 적용한 뒤 해석합니다. |

### 기초값, 역할값, 컴포넌트값

기초값(Primitive)은 팔레트 색처럼 직접 정의한 값입니다. 역할값(Semantic)은 기본 본문색처럼 **외부 프로젝트가 사용할 이름**입니다. 같은 역할을 제공하는 프리셋은 역할 키와 타입을 공유하고, 각자의 기초값을 선택합니다. 컴포넌트값(Component)은 특정 컴포넌트를 독립적으로 조정해야 할 때 추가합니다. 세 계층은 이름과 참조 관계로 표현할 수 있으며 기본 파일 하나에 함께 둡니다.

아래는 `tokens.json`의 형식 예시입니다. `color.text.primary`와 `component.button.label`은 기본 테마에서 같은 색으로 해석됩니다.

```json
{
  "color": {
    "palette": {
      "ink": {
        "$type": "color",
        "$value": { "colorSpace": "srgb", "components": [0.12, 0.15, 0.18] }
      },
      "paper": {
        "$type": "color",
        "$value": { "colorSpace": "srgb", "components": [0.96, 0.97, 0.98] }
      }
    },
    "text": {
      "primary": { "$type": "color", "$value": "{color.palette.ink}" }
    }
  },
  "component": {
    "button": {
      "label": { "$type": "color", "$value": "{color.text.primary}" }
    }
  },
  "space": {
    "md": { "$type": "dimension", "$value": { "value": 16, "unit": "px" } }
  }
}
```

## 추가 테마 적용 순서

1. 기본 `tokens.json`을 읽습니다.
2. 추가 테마를 선택했다면 해당 파일에 있는 토큰만 **동일한 경로의 토큰 단위로** 교체합니다. 역할 키와 타입은 유지합니다.
3. 포인트 색상 교체를 지원하고 사용자가 대체 색상을 골랐다면, 세 포인트 역할 키를 선택한 묶음의 대응 토큰에 함께 연결합니다. 선택을 생략하면 기본 묶음을 사용합니다.
4. 합쳐진 결과에서 참조를 해석합니다. 이 순서여야 컴포넌트가 현재 밝기와 포인트 조합의 값을 받습니다. 여러 테마의 소스와 적용 순서를 명시할 때는 DTCG Resolver 형식을 사용할 수 있습니다. [DTCG Resolver Module 2025.10](https://www.designtokens.org/tr/2025.10/resolver/)

위 예시에 대응하는 `themes/dark.json`은 본문색 하나만 재정의합니다.

```json
{
  "color": {
    "text": {
      "primary": { "$type": "color", "$value": "{color.palette.paper}" }
    }
  }
}
```

다크 테마에서는 버튼 글자색도 `color.palette.paper`로 해석됩니다. 간격 `space.md`는 두 테마 모두 16px입니다.

## 교체 가능한 포인트 색상

포인트 색상 교체는 선택 기능입니다. 이 기능을 제공하는 프리셋은 아래 세 역할을 모두 `$type: "color"`로 정의합니다. 외부 프로젝트는 역할 키를 참조하고, 프리셋은 각 묶음에 고유한 ID와 표시 이름을 정합니다.

| 공통 역할 키 | 쓰임 |
| --- | --- |
| `color.accent.base` | 주요 버튼 바탕, 강조 링크, 선택 표시 등에 사용하는 기본 포인트색입니다. |
| `color.accent.hover` | 주요 동작에 포인터를 올리는 등 강조 상태에서 사용하는 포인트색입니다. |
| `color.accent.ink` | 기본·강조 포인트 바탕 위에 놓이는 글자와 의미 있는 아이콘의 전경색입니다. |

각 묶음은 `color.<id>.base`, `color.<id>.hover`, `color.<id>.ink`에 값을 둡니다. `tokens.json`의 공통 역할 키 세 개는 기본 묶음을 참조하므로 선택 정보 없이도 사용할 수 있습니다. 밝기 테마 파일에는 해당 테마에서 달라지는 값만 기록합니다. `design.md`에는 기본 묶음, 선택 가능한 ID와 표시 이름, 플랫폼에서 선택하는 방법을 적습니다.

예를 들어 Ondo에서 다크와 세이지를 고르면 버튼 바탕은 `component.button.fill` → `color.accent.base` → `color.sage.base` 순으로 다크 테마의 세이지색을 얻습니다. 포인트만 교체하면 글자색과 강조 상태도 같은 묶음을 따르고, 화면 바탕·일반 본문·오류색은 현재 밝기 테마의 값을 유지합니다. 이후 밝기만 바꾸면 선택한 세이지 묶음이 새 밝기의 값으로 표시됩니다. [Ondo 적용 예시](../presets/ondo/design.md#색상과-테마)

## 등록 검증과 시각 검토

| 확인 대상 | 통과 기준 |
| --- | --- |
| 등록 구조 | 필수 파일 세 개가 있고 JSON을 읽을 수 있습니다. 메타데이터의 필수 필드와 자료형이 맞고, 폴더명과 ID가 일치하며 카탈로그 안에서 ID가 고유합니다. |
| 토큰과 테마 | 기본 테마와 각 추가 테마에서 타입·값·단위가 맞습니다. 재정의한 역할 키의 타입이 유지되고, 모든 참조가 기대한 타입의 값으로 해석되며 누락이나 순환이 없습니다. |
| 포인트 색상 교체 | 지원하는 밝기와 포인트 묶음의 모든 조합에서 세 역할과 이를 참조하는 컴포넌트를 확인합니다. 각 설정을 따로 바꿔 다른 선택이 유지되는지도 확인합니다. |
| 포인트 대비 | 각 조합에서 `ink`를 `base`와 `hover` 위에 각각 측정합니다. 일반 글자는 4.5:1 이상, 큰 글자와 의미 있는 아이콘은 3:1 이상이어야 합니다. 포인트색을 링크 글자로 쓰면 실제 표면에 대한 글자 대비를, 컨트롤 식별 경계나 포커스 표시로 쓰면 인접 색에 대한 3:1 대비를 확인합니다. |
| 독립성 | 프리셋 폴더를 다른 위치에 복사해도 문서와 토큰을 읽고 포함된 에셋과 미리보기를 열 수 있습니다. 파일은 프리셋 안에서 상대 경로로 연결합니다. |
| 시각 검토 | 대표 화면을 실제로 열어 정보 위계·배치·본문 가독성을 디자인 원칙과 대조합니다. 지원하는 테마별로 대비를 확인하고, 상호작용 요소의 포커스·비활성 등 해당 상태를 점검합니다. |

등록 검증과 시각 검토 결과는 별도로 기록합니다. 대표 화면이 준비되면 해당 화면을 확인한 뒤 시각 검토를 완료할 수 있습니다.
