# Design Systems

AI와 함께 디자인 프리셋을 설계하고, 여러 소프트웨어 프로젝트에서 다시 쓰기 위한 개인용 디자인 시스템 라이브러리입니다. 프리셋 하나에는 어떤 경험을 만들려는지 설명하는 디자인 원칙과 그 원칙을 화면에 적용하는 데 필요한 토큰, 컴포넌트 명세, 에셋을 함께 담습니다.

## 프로젝트 구조

```text
Design Systems/
├── README.md               프로젝트 목적과 사용 방법
├── AGENTS.md               AI 협업 모드와 변경 승인 규칙
├── ROADMAP.md              개발 단계와 완료 기준
├── docs/
│   └── preset-format.md    모든 프리셋이 따르는 구조와 작성 기준
└── presets/                프리셋마다 독립된 폴더를 두는 위치
```

현재는 라이브러리의 구조와 운영 규칙을 정한 단계입니다. 등록된 프리셋은 0개입니다. 공용 Codex Skill과 시각적 관리 도구의 개발 순서는 [로드맵](ROADMAP.md)에 정리했습니다.

## 프리셋을 만들거나 복제할 때

1. **탐색** — 사용할 화면, 대상 사용자, 원하는 분위기를 정하고 레퍼런스를 비교합니다. 이 단계의 제안은 대화에 남깁니다.
2. **설계** — 정보의 우선순위와 배치, 색과 서체의 역할, 주요 컴포넌트의 동작을 정합니다. 합의한 내용을 문서에 반영할 때는 대상과 범위를 지정합니다.
3. **작성** — 제작을 지시하면 공통 규격에 따라 `presets/<id>/`를 구성합니다. 기존 프리셋에서 시작할 때는 폴더 전체를 복사하고 새 폴더명과 메타데이터의 ID를 일치시킵니다.
4. **검토** — 토큰과 파일 참조를 점검하고 미리보기를 열어 실제 화면이 디자인 원칙과 맞는지 확인합니다.

프리셋 내부의 파일별 역할은 [프리셋 규격](docs/preset-format.md)에, 단계별 작업 권한은 [협업 지침](AGENTS.md)에 설명되어 있습니다.

## 외부 프로젝트에서 사용할 때

1. 라이브러리 루트 `%USERPROFILE%\Documents\Design Systems`의 `presets/`에서 후보를 찾습니다. 등록된 프리셋의 설명과 태그로 후보를 좁힌 뒤, 디자인 원칙과 미리보기를 보고 선택합니다.
2. 선택한 프리셋의 원본은 읽기 전용으로 참조합니다. 필요한 토큰과 에셋을 대상 프로젝트로 복사하고, 대상 플랫폼의 테마나 스타일에 연결합니다. 예를 들어 같은 본문 색상 토큰을 웹에서는 CSS 변수에, 데스크톱에서는 테마 리소스에 연결할 수 있습니다.
3. 대상 프로젝트에 사용한 프리셋 ID와 현지화한 항목을 기록합니다. 한 제품에만 필요한 색상이나 간격은 그 프로젝트에서 조정합니다. 공통 원본에도 반영할 변경은 이 라이브러리에서 별도로 요청합니다.
